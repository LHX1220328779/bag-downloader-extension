# 项目分析与 v2 实现记录

日期：2026-11-05。项目是无构建步骤的 Chrome Manifest V3 扩展，原版本 1.2.0。当前目录没有 Git 元数据，因此本次直接修改工作区，没有创建提交或 PR。

## 原架构及问题

原实现通过页面 MAIN world 读取 Vue 表单，隔离脚本转发筛选，service worker 查询 `/api/bag/search`，offscreen 文档下载并写入 IndexedDB 记住的目录句柄。

发现并处理：

1. 表单捕获强制要求 `truck_no/mine/type/break_source` 四字段，只支持 search 表单。table 使用 `name` 代表车辆且缺失来源；后台标签也可能覆盖前台选择。
2. 查询、恢复依赖数组下标，动态加入早时间文件并排序后可能把结果记到另一文件。现在使用稳定 `jobId` 与服务器路径匹配。
3. service worker 把不认识的 `offscreen:*` 消息也异步回复，可能抢在 offscreen 前回答“未知指令”。现在明确让下载文档独占回复。
4. 原停止/重新执行没有运行代次标识，旧查询响应可能进入新执行轮次。现在使用 `runToken`，并在发请求、写文件和最终提交前再次核对任务。
5. 原目录选择和授权先等待 IndexedDB，再调用需要用户手势的浏览器 API。现在句柄预缓存，选择器/授权在按钮同步调用栈触发。拒绝授权状态不会被误当成目录缺失。
6. 原有任务无法切换到新目录。现在任务可单独授权和切换目录；切换后重新核对下载完成情况。
7. 原来同名即跳过，而 `getFileHandle(create:true)` 可能留下空文件。现在按完成凭据或精确 HEAD 长度核对，验证流长度后才提交，失败清理本次新建的零字节占位。
8. 查询带日期参数在部分请求返回 HTTP 500；不带日期但限定车辆/矿区/类型的查询正常。现在仅对此错误回退，并保留所有非时间筛选，之后严格在本地过滤时间，绝不全条件为空查询全库。
9. 真实 `/api/bag/download` 返回 8099 端口文件服务，而原清单只声明 8080。已补充 8099 下载源并验证其 HEAD 返回正常。
10. 原 CSS 存在缺失选择器和多余闭合括号。已修复，完善窄侧栏、状态文字与大清单分页。
11. 根据后续反馈，“任务设置”的四项恢复只读，值仅来自 `/table`、`/search` 网页捕获；移除手动设置缓存对任务参数的影响，同时删除说明性小字和刷新入口。缺少来源字段时显示“不限”，不沿用手动来源。保留实际状态、进度及错误提示。

## 任务状态与队列

- 任务：ready → running；车辆不可用进入 waiting_vehicle，恢复自动回 running；用户停止进入 stopped；目录问题进入 error；全部已处理后 done（保留失败数）。
- 回传包：pending → submitting → submitted → confirming → done。网络提交结果不明确进入 uncertain，持续查询核对。已尝试/已提交的包（包括旧失败记录）持续核查，不在离线恢复或重载时自动重建；下载失败限次重试。
- 下载包：pending → downloading → done，或失败后限次重试/failed。
- 回传完成以 search 中相同文件名和规范录制时间的记录为证据；MDC 与 NAS 路径不同，不能比较 dirpath。
- 搜索结果增量合并，保留已完成、下载中、失败记录；按 jobId 处理结果，避免排序造成错配。
- 提交使用单包唯一备注或批次唯一备注，便于从服务器记录确认结果。批次内同一分钟有多个包、又没有精确文件名时，只确认该批已提交，不把某条成功记录分配给其他包。对于旧的只含分钟时间的运行中记录，保守等待，不能据此认定某个精确文件完成。
- 每次提交前都检查在线状态新鲜度，停止后的旧轮次不能继续提交。已发到服务器的请求没有事务撤销能力，停止后可能仍被接受，恢复时核对。
- 轮询各任务、目录/同名写入锁、持久 job 恢复与 alarms 共同保障侧边栏关闭后继续运行。

## 实现选择与边界

- 原站点 MDC 新任务来源固定 mdc，不能用不存在的字段伪造其他来源。插件在创建前明确限制为 mdc/不限，其他来源继续用于下载任务。
- MDC 清单是执行时快照；未来录制的数据不自动新增到已完成任务。重新执行重新发现。
- Chrome worker 对长时间 fetch 的限制不适合直接加载慢 MDC 清单，因此移到 offscreen 文档；车辆监测和 search 保持独立。
- 正常 15 秒轮询，worker 休眠后 30 秒 alarm 兜底；不是硬实时系统，浏览器关闭/系统休眠时不能监测。
- 不自动操作网站鼠标、不抢前台焦点。告警用页面顶部固定横幅、红色任务卡片、扩展图标和浏览器通知；通知展示仍受系统通知设置影响。
- 同名本地文件通过精确长度和完成凭据校验，不提供服务器没有提供的内容哈希保证。
- 文件直接写入所选目录，变更任务目录后保留旧文件。v2.1.1 目录授权即生效，不再依赖 txt 路径确认。保留旧完整路径，新目录显示真实目录名；已有授权路径的现有子目录可以输入切换，未知路径须系统选择。

## v2.1 继续开发与恢复保障

- 保持纯插件，支持 Chromium 120+ 的 Chrome/Edge，不增加本机桥接程序。目录句柄与完成凭据继续使用原 IndexedDB；任务、回传提交记录、队列、秒级范围及折叠状态持久保存在 storage.local，不清空旧数据。
- 浏览器启动/扩展重载保留任务 ID 和运行代次，恢复孤立下载 job；已停止及未执行的任务不自动启动。使用 storage.session 标识本次浏览器会话，重启后核验本地已完成文件，worker 休眠不会重复核验。
- 核验期间保留已完成计数；凭据匹配精确服务器路径、文件大小和修改时间时直接跳过。缺少凭据时用 HEAD 的精确长度核查。即使文件已落盘但后台结果未保存，也不会重复 GET 完整文件。不存在、零字节及长度不符的文件重新下载。
- 写入只有完整字节数核验后才能原子提交。GET 缺少长度时使用 HEAD；长度无法核验、206/Content-Range 或压缩响应不标记为完成。网络中断和停止保留已有完整文件，清理本次新建的空占位。
- 目录选择先保存句柄记录，再确认真实路径；确认取消或位置不一致后可重试。防止下载完成事件先于下载 ID 保存而把 done 覆盖成 saving；重启可用随机 URL 找回改过文件名的校验记录。只清理本插件本次随机 URL 创建的校验文件。
- 回传记录持续核查与批量提交分开，慢提交不阻塞车辆状态和文件入库检测。已尝试回传的锁在升级、离线及重启后保持，正常/成功记录优先于重复失败记录。
- 使用苹果系统风格的颜色、圆角、按钮和继承的系统字体，兼容明暗主题；四项捕获值保持只读。所有创建按钮与目录选择按钮一致，任务可折叠，进度列表仅显示录制日期后的文件名。
