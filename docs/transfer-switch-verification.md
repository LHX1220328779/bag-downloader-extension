# v2.5.7 回传开关修复与验证

日期：2026-11-11。

## 问题与实现

旧界面的点击处理使用内存任务快照反转回传状态。异步加载先替换该快照，再等待目录检查，最后才渲染；因此可见按钮仍被勾选时，内存状态已经关闭，再点击反而发送开启请求。

v2.5.7 按按钮当前的 `aria-pressed` 确定点击目标，同步显示勾选结果。`taskTransferSelections` 独立保存用户选择与版本，创建和明确切换时原子更新；进度刷新只读取。每次切换携带请求编号，旧快照与迟到回复不能覆盖最新选择，关闭重开侧栏、后台心跳及浏览器重开继续使用保存的选择。

选择保存、服务器查询和等待确认期间显示刷新标识，并设置 `aria-busy`；错误重试显示原因，保留选择。服务器确认与用户选择分别显示，未被后台接受的点击不假报保存成功。后台返回“未知指令”时，提示在扩展管理页重新加载插件，以避免新版界面与旧后台同时运行。

暂停仅调用 `/api/break/pause/{record_no}`，恢复仅调用 `/api/break/cancelpause/{record_no}`。原记录、任务 ID、运行代次、完整目录和已完成进度保留。任务标记、单包标记、保存的批次标记与已确认归属用于限定控制范围，车辆、来源和矿区再次核对；同名文件或分钟时间不足以证明归属。迟到提交会按最新选择补控制，已成功记录不重建。

真实车辆处于离线状态，不能以本次结果证明在线传输流量的连续性。没有操作其他生产任务，没有删除或重新建立任何生产回传，也没有改变任务目录。
