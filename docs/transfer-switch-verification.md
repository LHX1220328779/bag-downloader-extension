# v2.5.10 回传确认与离线恢复修复验证

日期：2026-11-11。

## 问题与实现

指定任务再次开启回传后，按旧规则确认的 49 条未完成记录已解除暂停，另有 7 条历史记录仍为 `pause`。这些记录在本地保存了提交批次、时间、接受状态和原编号，服务器却不再返回任务备注；旧归属规则将它们排除。旧确认逻辑还允许同批任意一条记录代表所有包，因此在遗漏七条时仍报 `settled`。此前的真实验收只核查了带标记或已记忆的 50 条记录，没有覆盖这七条历史绑定。

v2.5.9 在普通进度核查时就保存已确认的原编号。旧任务丢失备注时，用已接受且锁定的提交、有效批次、提交时间、原编号和完整包名恢复历史绑定，并再次核查车辆、矿区、来源和类型。已确认的原记录优先于同名外部记录，已绑定编号逐条核对，无编号批次核对记录数量。备注或文件名后来缺失时，仍通过保存的绑定查询和更新每包状态。

原记录的暂停和恢复不依赖车辆在线。取消暂停后，站点使用 `cancelpause` 表示解除暂停等待调度，界面与 `waiting` 一并显示“等待回传”，清除旧暂停提示。实际传输与新建尚未提交的包仍等待车辆在线。

旧界面的点击处理使用内存任务快照反转回传状态。异步加载先替换该快照，再等待目录检查，最后才渲染；因此可见按钮仍被勾选时，内存状态已经关闭，再点击反而发送开启请求。

v2.5.7 按按钮当前的 `aria-pressed` 确定点击目标，同步显示勾选结果。`taskTransferSelections` 独立保存用户选择与版本，创建和明确切换时原子更新；进度刷新只读取。每次切换携带请求编号，旧快照与迟到回复不能覆盖最新选择，关闭重开侧栏、后台心跳及浏览器重开继续使用保存的选择。

v2.5.8 将文字刷新符号改为细圆弧 SVG，在选择保存、服务器查询和等待确认期间显示，并设置 `aria-busy`。等待时按钮使用淡色，勾选框保留且可以继续切换。圆弧位置始终保留，加载前后按钮宽度保持稳定；正常状态只放在悬停提示和辅助技术的状态区域，不增加卡片行高。支持明暗主题和减少动态效果。错误仍在按钮下方提示原因，保留选择；未被后台接受的点击不假报保存成功。后台返回“未知指令”时，提示在扩展管理页重新加载插件。

暂停仅调用 `/api/break/pause/{record_no}`，恢复仅调用 `/api/break/cancelpause/{record_no}`。原记录、任务 ID、运行代次、完整目录和已完成进度保留。任务标记、单包标记、保存的批次标记与已确认归属用于限定控制范围，车辆、来源和矿区再次核对；同名文件或分钟时间不足以证明归属。迟到提交会按最新选择补控制，已成功记录不重建。
